# 外部 Agent 接入评价

评价对象是仓库中的 Agent 协议、两个示例客户端和服务端接入实现。没有把未提供程序、模型或运行记录的第三方 Agent 视为已经实测。

## 结论

**接入架构适合继续使用，示例程序适合作为开发模板。** HTTP + 座位令牌不绑定语言或特定 LLM 框架；服务端独立裁判、逐子合法性校验、局面序号和动作日志形成了清晰边界。本次补齐了原先影响可信评测的事件推送、超时刷新、过期动作及令牌轮换问题。

示例客户端都是确定性脚本，没有 LLM 调用、工具规划、长期记忆或自主任务分解，不能据此宣称已经接入成熟通用智能体。

## 实际运行样本

2026-11-13 在本机使用独立内存数据库和本地普通难度 AI 验证：

| 场景 | 完整结束 | 总落子数 | 结果 | 超时兜底次数 |
|---|---|---:|---|---:|
| `example-client` 执黑，对本地 AI | 是 | 15 | 本地 AI 胜 | 0 |
| 两个 `example-client` 对打 | 是 | 20 | 黑方胜 | 0 |
| `attach-agent` 默认策略执黑，对本地 AI | 是 | 11 | 本地 AI 胜 | 0 |

样本说明协议能跑完对局、没有混入兜底动作。每种场景只有一个确定性样本，不能据此推导胜率、等级分或第三方模型棋力。本次没有修改两个示例的决策策略。

可重复执行 `npm run evaluate:agents`；详细输出存放在 `artifacts/agent-evaluation.json`，包含结束状态、落子数、胜者、兜底次数和本机耗时。JSON 棋谱的玩家元信息及 CSV 也增加了兜底次数，便于筛除受兜底影响的对局。

## 分项评价

| 方面 | 评价 |
|---|---|
| 接入便利性 | 较好。任意语言能实现读取局面、选择合法点和带 `turnId` 提交三步流程。 |
| 裁判隔离 | 较好。Agent 没有修改规则、代替另一座位落子或取得其他账号 Key 的接口。 |
| 时序可靠性 | 本次已验证轮询不续期、重启不增加时限、过期动作被拒绝、迟到兜底不会覆盖真实动作。 |
| 实时性 | SSE 已验证连续换手事件；不支持 SSE 的进程仍可轮询。慢连接有数量和缓冲上限。 |
| 凭据管理 | 令牌仅存摘要，换发后旧令牌与旧事件连接失效。示例现在拒绝远程明文 HTTP 和重定向，并支持用环境变量给 attach 客户端传令牌。 |
| 客户端完整性 | 已增加请求超时、响应大小上限，以及 attach 时校验目标对局。仍是示例，尚无长期运行的故障统计。 |
| 评测公平性 | 可以用作实验接口；正式比较还需固定版本、时限、先后手、开局集，并剔除兜底样本。 |

`example-client` 的棋型评分是简化示范，并且将“长度 × 开放端权重”的分数与 6 比较，不能当成严格连六判断器。`attach-agent` 默认只优先靠近中心。这些局限已记录，本次按要求不优化策略。

## 在网站接入自己的 Agent

先登录网站创建含 Agent 席位的对局，再由房主在页面领取令牌。外部程序持令牌访问 HTTPS 站点，不需要共享 LLM Key。

```powershell
$env:THICK_EARTH_AGENT_TOKEN = '页面领取的座位令牌'
node agents/attach-agent.mjs <gameId> https://你的站点
```

`example-client` 的自动建局、领取令牌演示针对免登录的本地桌面服务；网站的这些操作需要登录会话，建议使用上述页面建局加 attach 的方式。

外部 Agent 由自己的进程决定策略；网站共享 LLM 是服务端 AI 席位的另一条路径，两者都走相同规则裁判。若需评价某个具体第三方 Agent，应收集其版本、调用次数、合法动作率、过期提交率、延迟分位数、兜底比例及固定对手下的双先后手样本。
